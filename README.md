# RetroBooth v0.9 - Android and Windows build repository

**Start with [START_HERE.md](START_HERE.md).** Three independent manual GitHub Actions workflows build Android TEST APK, Windows installer/portable EXE, and full verification separately. Native binaries are generated by successful CI jobs, not bundled in this source archive.

The common interface retains Edge-to-edge CRT / Heritage TV, film and soft-mono webcam treatment, one-action fixed-duration capture, local save, timed QR, and opt-in private PHP cloud delivery. Hostinger is separate from the local APK/EXE; no hosting credentials are baked into builds.

## Build on GitHub

Copy project CONTENTS including `.github` into repository root, push to default branch, then Actions > **RetroBooth - Build Android APK** OR **RetroBooth - Build Windows EXE** > Run workflow. Native builds are independent of the long **RetroBooth - Full Verification** job; run full verification separately before event use. Windows ARM64 is opt-in. Program artifacts are separate from Evidence and unsigned developer artifacts.

- Android output: `RetroBooth-v0.9.4-Android-TEST.apk`
- Windows output: `RetroBooth-0.9.4-alpha.1-Windows-x64-Setup.exe` and `...-Portable.exe`
- Workflows: `.github/workflows/build-android.yml`, `build-windows.yml`, `verify-all.yml`

A successful build is not event readiness. Follow the guide's device acceptance routine. No GitHub account was accessed or deployment performed while preparing this package.

## Developer commands

```sh
npm run desktop:prepare
npm test
npm run test:native-core
npm run desktop:install
npm run desktop:start
# On a Windows development machine:
npm --prefix desktop run package:win:x64
# Web packages and editable source archive:
npm run package:web
npm run package:source
```

Root build/tests use Node built-ins. Desktop installation needs registry access. Direct Electron/build-tool versions are pinned; the first CI run generates a resolved npm lockfile. Review and commit the `desktop/package-lock.json` from Windows Evidence for subsequent `npm ci` builds. It was not fabricated offline.

## Preservation and security

- Android app ID and browser database/schema retained; versionCode 9. Keep the existing signing identity for upgrades.
- New Windows origin `retrobooth://app`; profile `%APPDATA%/Luce RetroBooth`. No automatic import of Chrome/Android clips. Installed/portable share the same Windows-user profile.
- Restrict desktop to bundled assets, origin-bound narrow IPC and one explicitly approved HTTPS cloud host. Node is not exposed to the renderer. No TLS/CORS bypass.
- For an existing cloud, add the exact desktop origin to private `corsOrigins`; preserve keys, data and all other required origins. Create a separate device credential per installation.
- No background auto-updater or automatic deployment; no private keys, recordings or live cloud config in source. End-user devices do not need Node/JDK for the generated apps.
- Native media durability remains WebView/Chromium/IndexedDB, not process-kill-safe recording. Export and verify independent copies.
